## What the consultations were for

Across these four snapshots, the parent recipes entered consultation 10 times. One of those visits included a referral to another owner. The 10 visits contained 43 agent calls with recorded replies: 18 by receiving authors, 16 by assessors and nine by agents responding for the requester. This counts work inside the consultation. The parent’s decision to initiate it, blocked delivery attempts, and child jobs are outside that total.

| Job | Parent consultation visits | Agent calls inside | Why |
| --- | ---: | ---: | --- |

## Checks for similar structure

The follow-up inspected Adaptive3 at `2aa5580` and reused the four job histories above. The examples below distinguish an observed interruption from behavior reproduced with a small fixture.

| Decision | Evidence | What the regression should establish |
| --- | --- | --- |
| Which files to show with a recovery question | The switcher’s two recovery forms reported 11 and 13 file issues, including descriptions of files the form had not attached. Sidebar’s form reported six failed links while the attached report still contained a clear question. The author prompt requires a complete description list even for reused files. [Author prompt](https://github.com/colony-2/recipes/blob/2aa5580/recipes/adaptive3/prompts/execute.yaml#L123-L134) · [Recovery form](https://github.com/colony-2/recipes/blob/2aa5580/recipes/adaptive3/backstop.yaml#L208-L220) | Reuse descriptions for retained files. An invalid optional link leaves the question readable. A missing essential document returns to the author. |
| Whether a negotiation explains this job’s origin | The file validator reads the visible Markdown link label to infer the relationship. In an isolated run, changing “Parent job sample” to “Originating job sample”, with the same URL, file and request, changed the title from “Request” to “Why this job exists”. Both versions passed validation. This affects display. [Origin and title inference](https://github.com/colony-2/recipes/blob/2aa5580/recipes/adaptive3/tools.yaml#L93-L116) | Editing a report heading or link label leaves the sender, receiver and relationship intact. |
| Whether a recovery proposal changed after a question | The discussion branch compares action text and stage. I exercised its condition in c2j with the same stage. “Rerun the browser check” kept the existing proposal. “Run the browser check again” took the same reassessment branch as “Publish the release”. This checks routing only. [Discussion decision](https://github.com/colony-2/recipes/blob/2aa5580/recipes/adaptive3/discussion.yaml#L110-L125) | A paraphrase keeps the displayed proposal. A changed operation gets a fresh proposal, and Apply always refers to the one displayed. |
| Which phases recovery may return to | I ran the current recovery policy against its existing accepted-plan fixture in c2j. The original allowed Implementation, Outcome and Integration. Changing just the upstream summary, or adding one supporting document reference, made all three unavailable. The receipt and candidate stayed the same. This fixture tests available destinations. The recorded block in the switcher came from its automatic-return limit. [Recovery policy](https://github.com/colony-2/recipes/blob/2aa5580/recipes/adaptive3/backstop-policy.yaml#L14-L24) · [Baseline fixture](https://github.com/colony-2/recipes/blob/2aa5580/recipe-tests/adaptive3/backstop-policy.test.yaml#L3-L44) | A wording edit allows resuming covered work. A superseding human decision invalidates the earlier scope. A changed candidate still needs its applicable verification. |
