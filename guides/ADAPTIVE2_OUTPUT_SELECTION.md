# Current evidence in adaptive2 results

A consultation carries the files its participant explicitly selected. Declaring an existing input retains its original artifact identity; a new reply file belongs in the current turn directory. Omitting an earlier proposal leaves it at its producer. It does not make the proposal a deliverable in the next turn.

The record boundary replaces the current document map and filters annotations by delivered path and immutable reference. References compare without the delivery `name`, while retaining producer and content identity. Same-name replacements therefore cannot inherit stale annotations. The binding helper can strip a selected request directory and add a consumer prefix; it applies that alias to annotation IDs, lineage and matching source references as well as file names.

Nested requests receive their selected request directory, rebased to the request root. Returned selected evidence receives one downstream prefix. Accepted assignment records keep the receiver's original handoff identity independently of its incidental supporting files. That identity is compared before execution; changing, omitting or ambiguously selecting an assignment cannot authorize a child.

Presentation adds a human conversation and, when a current consultant summary is selected, its summary page. It does not select historical attachments from transcript entries. Historical stored files have producer job, task ordinal and artifact-name locators. Current generated links require a selected path and matching immutable identity. Conversation prose remains available even when an earlier attachment is no longer selected. A quoted historical link inside participant-authored prose is not a request to deliver that file.

Coordination binds selected evidence separately from lifecycle records. Its consultation record retains request, target, outcome, summary, accepted handoff identity, pending execution requests and approval receipts needed by orchestration. Nested accepted advice is expanded once; the enclosing record no longer contains the expanded agreement list. The public build result projects concise coordination outcomes without their accepted-artifact maps or complete child outputs.

The shared child collector sends selected child documents through its document channel and lifecycle/failure facts through its result channel. The generic await helper retains the full native child output at the producer because consultation routing, cell creation and other immediate consumers still need it. Later coordination records and final build results project that output instead of copying it.

Invalid reports retain their current inputs, newly arrived child diagnostics and correction evidence until corrected. A valid report carries declared files, formal request/acceptance documents and newly arrived child results for the next consumer to inspect. It does not restore all previous child document maps after every report. This preserves child-report correction while allowing the next valid selection to retire old evidence.

Reviews use the selected current packet and identity-matched sources. Kernel review-content still reads legacy conversation records when supplied for producer inspection; its historical-reference classification does not add files to the caller's current document map. Approval recovery inspects the producing human-input tasks and their receipts; it does not require a copied public consultation tree. Prior and cross-parent recovery retain their scope and replacement checks.

Selected references may appear in both a delivery map and its annotation/provenance metadata. An accepted handoff also remains in an internal authorization record so later evidence selection cannot change the accepted assignment. Distinct accepted assignments can explicitly select the same useful evidence. Native session references and human approval receipts remain where their consumers need them. These are bounded by the selected work, rather than an automatic union of all history. Explicitly selecting an arbitrarily large packet can still exceed the runtime limit.

The propagation regression creates three groups of 23 persisted artifacts, exercises nested advice and multiple consultation turns, and runs the real build entrypoint through review and merge. A fixture measures the complete returned build result with native serialization, asserts it is below 262144 UTF-8 bytes, and retrieves a retired document through its recorded producer. This test does not replace file bodies, truncate prose or raise the runtime limit.

The integrated renderer formats native presentation values and reads only selected files whose heading is needed. Consultation continuation uses native state outputs and transition payloads; public results do not expose serialized control state. Recorded runtime restart validation remains the native-state sibling assignment; this propagation regression does not certify restart behavior.

The older `recipes/adaptive/consultation.yaml` and `adaptive/coordinate.yaml` retain their legacy public session/document contracts; they are not the root build's default consultation route. The shared initializer, bindings, child collector and review helpers are covered here, but this change does not promise selection-only behavior for arbitrary custom consultation recipes. Adaptive2 projects a custom consultation's public record and filters delivered annotations; the custom producer remains responsible for choosing its own useful final artifacts.

Child outcome projections select existing keys instead of constructing missing keys with null values. This preserves optional Boolean defaults used by development recovery, including completed unsuccessful children that return only `status: failed`. Shared collection, coordination records and final public coordination use the same selection rule.
