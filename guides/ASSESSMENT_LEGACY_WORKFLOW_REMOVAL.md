# Legacy workflow removal and retained test repair

Scope: remove retired workflows, preserve adaptive, and investigate all remaining
failures. This fits the recipes cell. Reusable runtime fixture features belong to
c2j; that boundary is described separately below.

The implementation follows [the removal plan](LEGACY_WORKFLOW_REMOVAL.json) and
[retained expectations](../recipe-tests/retirement-statements.md). It builds on
recovery commit `5c6a6fb` and the [158-case audit](AUDIT_ADAPTIVE_DEPENDENCIES_AND_LEGACY_FAILURES.md).

## Removed and retained

Removed 47 production YAML files: the old heavy/light implementation, old hooks,
ticket/job workflows, superpowers, and eight exclusive kernel helpers. Removed
178 recipe/test files in total, including exclusive suites, fixtures, scenarios,
and the obsolete disabled legacy case. No compatibility entrypoints remain.

Retained `build.yaml`, all adaptive YAML, shared response schemas, root creation,
creation's ten kernel includes, and independent smoke/documentation examples.
Adaptive production code and its 271 test cases are unchanged. Its README now
correctly says the old implementations are removed. The README, kernel/creation
guides, authoring references, test ownership guide, and repository verification
script now point to retained sources.

Historical expectations that mix creation/shared coverage with retired callers
have explicit scope notices. Removal does not silently reinterpret old passing
claims as coverage of adaptive.

## Retained fixes

### Large review results

The creation review renderer returned structured metadata through
`command_execution.stdout`. c2j exposes a bounded stdout preview there; the
annotation overflow case exceeded it and failed JSON parsing before review.
The renderer now uses a local extension manifest and returns typed output directly.
Its Python producer remains supplied by the packaged recipe. The same task still
writes the complete brief, evidence and provenance as individual artifacts.
Consumers no longer parse a log preview for the structured result.

The separate source-overflow assertion inspected a preview whose reason appeared
after a large body. The test inspector now prints the reason before its bounded
brief excerpt. Its original-artifact assertions remain; the production source
content is not truncated to make the test pass.

### Model and annotation test boundaries

Model-call assertions now identify the actual `#codex` or `#llm` selector instead
of treating every extension invocation as inference. The deterministic renderer
uses the extension protocol too.

Shared annotation tests now use the retained creation agent and actual shared
schema instead of retired heavy/light producers. Valid descriptors travel through
native artifacts, two namespaces and a review. Invalid types must fail the actual
schema before review; a mock claiming schema validity is not schema evidence.

The local Nix environment initially lacked the project's signed `colony2` cache,
so optional synthesis tests failed before reaching their mocked model responses.
The cache was configured for testing. CI already configures that cache and is
unchanged by this environment repair.

### Creation fixture boundary

The runtime test harness already registers seeded cells. Full creation cases
therefore cannot repeat native creation of those records. They isolate that command,
as the existing registered-cell publication suite already does; dedicated native
registration cases retain idempotency, conflicting identity and permission coverage.

After that boundary, the old full-creation mocks still provide `repo: alpha` or
`repo: beta`, which are cell names rather than portable repository identities.
The runtime now generates those identities per test. Static mock responses have
no way to reference them. Empty workspaces still require an explicit repo, so
removing that requirement from the production recipe is not a valid remedy.
The user chose to document the c2j requirement rather than change c2j in this task.
The affected suites remain enabled and their remaining failures must be reported.
Production registration, approved repository selection and publication remain
unchanged. See [the fixture-reference request](FEATURE_REQUEST_C2J_RUNTIME_FIXTURE_REFERENCES.md).

Clarification tests now expect the current brief/provenance generated by the
review helper while continuing to require no agent-authored supporting document.

## Why model-assisted synthesis remains disabled

This is an optional second model call in creation's retained review helper.
Adaptive already uses its working/review agents to author review summaries.

Commit `1b9846a` deliberately shipped deterministic briefs with `activation: false`.
The [activation notes](REVIEW_BRIEF_PRODUCTION.md) required real review-example
quality/readability evidence and an enforceable overall execution deadline,
including package setup and provider retries. Those gates were never completed.
It is not a c2j limitation, and passing mocked contract tests does not complete them.
This cleanup repairs the optional branch's tests without enabling it.

adaptive, rendering, synthesis or native registration failures in this run.

The full run exits nonzero: these creation gaps remain visible and cannot be
reported as passing. As requested, c2j fixture support is documented rather than
implemented here. Once it is available, replace aliases in proposal responses and
configuration artifacts, rerun these 18 cases, and inspect any failures beyond
that currently blocked boundary. Their later assertions have not been established
by this run.

`c2j test validate --directory .` also passes for all retained deterministic suites

into passing scenarios.

The static dependency scan resolves all 277 retained local recipe references.

documentation links resolve, and `git diff --check` passes. The native full run's

The source comparison against `5c6a6fb` confirms no changes to `build.yaml`,
