1. **Make the existing outcome assessment enforce visual evidence.** In adaptive2/prompts.yaml, require the assessor to judge visual impact from the actual request/diff, not from whether a README mentions screenshots. For implemented visual changes, require representative actual browser/application captures covering the changed surface and important states, with sufficient context to judge applicability to the candidate. Return revise/next: validation for missing evidence. A nonvisual change or explicit human exemption can pass with an explanation. Design mockups and unrelated test-failure screenshots do not satisfy implementation evidence.
2. **Make the existing summary/accounting check enforce delivery and local-link completeness.** The summary must explicitly declare each selected image and include it directly in merge-review.md source_paths under the current selector. A gallery is useful, but selecting only the gallery is insufficient. Before human review, evaluate the same selection used by review.yaml and verify required visual evidence is in that resulting document map, retrievable, and linked from the brief or attached gallery. Feed missing-file/source errors through the existing correction/revision flow. Validate actual selected refs, not just output-directory files or metadata claims. This belongs in the existing accounting/inspect/review assembly path, not a new review agent or human checkpoint. A shared selection helper may be warranted to avoid divergent preview and publication logic.

   Follow local links transitively through the review packet: review brief → supporting document/gallery → image or other evidence file. Check all selected review documents, not only the overview or screenshot gallery. Parse supported Markdown links, reference-style links, images, and supported embedded HTML link/image markup; ignore examples inside code. Resolve relative paths against the referring document's attachment path, normalize `.`/`..` and encoded filenames consistently with the viewer, and separate query/fragment suffixes from the artifact lookup. Fragment-only links require no additional attachment. External URLs are outside this attachment check.

   Every referenced local file must resolve to a retrievable artifact in the final form's documents map. A repository/scratch path, producer output, or artifact available only in an earlier task is not an attached file. Do not read arbitrary filesystem paths to satisfy review links. Use a visited set for cycles; if resource limits prevent a complete check, report incomplete validation rather than silently passing. Report the referring document, original link, resolved target, and link chain when useful, e.g. `merge-review.md → screenshots.md → evidence/desktop.png: missing from review attachments`. Route this through existing correction: select the retained file, retrieve/recreate missing evidence, or correct the link. Do not remove required evidence just to make validation pass.

   Clarify producer and summary prompts: every local evidence link is a promise that its target will be attached; a linked index/gallery also requires its linked files. Under the current direct-source selector, the overview must select those targets explicitly even when the prose links them indirectly. Preserve meaningful links during revisions and distinguish external source references from local review artifacts.
3. **Give the implementation agent the matching capture contract.** Tell it to capture actual UI during implementation/validation, publish individual image artifacts and a small gallery where useful, and retain producer references. Retrieve retained captures before rerunning the application. If capture is unavailable, record the attempted command and concrete environment failure; route through the existing intervention mechanism. Missing evidence must not become approval merely because its absence is disclosed. Avoid demanding production deployment or all browsers unless the assignment calls for it.
4. **Preserve evidence through follow-up reviews.** Keep applicable selected screenshots attached when revising or rebasing the review. Reuse is acceptable when the assessor establishes continued applicability; regenerate when the changed visual surface makes them stale. Do not copy every historical image or attach entire evidence trees.

Cortex/c2ops can separately investigate stable browser-font provisioning if this recurs; it is not a prerequisite for fixing the proven selection gap. No runtime rewrite is proposed. Recursive local-link validation is required; automatically attaching arbitrary repository files is not. Selection remains explicit, and validation checks its completeness.

Validation should use native recipe fixtures at the actual artifact and form-selection boundary, including the revision route. Scripted verdicts validate routing, not model judgment. Then use one bounded live UI trial to check whether the assessor recognizes omitted visual evidence.
