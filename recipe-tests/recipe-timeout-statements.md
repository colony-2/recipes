# Recipe execution timeout acceptance

These statements implement the approved direction: remove recipe-imposed timeouts. Each Expected outcome cell is one statement of at most 30 words. IDs are stable. Prior content, artifact, approval, cancellation and error contracts remain applicable.

Dependencies: **S** = repository source and ordinary source-inspection tools; **N** = selected project-pinned c2j, disposable Git/JobDB/artifact storage, Nix/cache access and declared helper packages; **M** = N with scripted external model decisions and human responses. No live model credentials, infrastructure or Docker are required. Harness and CI safety limits remain in force. Source unit checks may run as assertions in the native runner.

RT05–RT08 require native production helper execution and baseline-sensitive boundary evidence without minute-scale waiting. RT03–RT04 and RT12 require the complete production review path; a fixture-built imitation form is insufficient. See the execution design for complementary fixture paths, controls and mutation checks.

The approved direction explicitly supersedes the old timing policy, including B01's deadline prerequisite, B07's 60/130-second promise and the old expired-bundle assertion. Preserve those references and explain supersession in the affected repository statements. Independent evidence, validation and review expectations are unchanged.

Acceptance requires passing relevant existing suites and the deterministic suite under existing harness bounds. Deployment and incident recovery are not acceptance conditions. This file defines checks; it records no passing implementation results.
