## Preservation and execution

These statements add annotation coverage without replacing or weakening `recipe-tests/review-brief-statements.md`, `review-evidence-preservation-statements.md`, `completion-review-statements.md`, `build-kernel-statements.md`, and existing artifact, consultation, accounting, revision and compatibility scenarios. There are no removals, changed existing expectations, or deprecations; no deprecation plan is required. Content-production synthesis bounds, factual evaluation gates and fallback remain unchanged.

Dependencies in the tables:

- **N**: native c2j test runner, Git, declared Nix helper packages; mock agent/model responses and human answers, but execute production collection, assembly and rendering includes.
- **W**: N plus the supporting c2j runtime and authoritative serialized validation/transport fixtures. Producer helper tests alone cannot establish this evidence.
- **D**: W plus deployment inventory, pinned release evidence and strict-client compatibility fixtures. Visual rendering assertions belong to Cortex.

Each table outcome is a test statement of at most 30 words; annotations occupy separate columns. Filenames identify existing production boundaries, not a requirement to place all helper logic in those files. Extend native suites and publish this plan as a C2 artifact. Assert actual emitted input forms, exported refs/sidecars, brief/provenance coverage and resulting routes. No implementation or tests have been executed in this phase.

## Acceptance evidence and limits

Run affected native artifact, review, consultation, build/light/create, revision and completion regressions through the workflow's approved validation path. Use mocked agent descriptors through real schema and collection boundaries; injecting already-normalized metadata alone cannot satisfy A01–A09. Exercise all direct review-form constructors, not merely kernel/review. Pair budget helper cases with actual production form assertions and original-document reachability checks.

W evidence belongs to c2j's authoritative runtime/serialized contract; D evidence additionally requires release and deployment compatibility records. Cortex owns visual assertions, not this repository. No supporting release tag/commit or authoritative fixture bodies are supplied here. Synthetic fixtures or an installed version string cannot substitute for those acceptance records. Missing W/D evidence must be reported as unverified and blocks annotated activation, while independent legacy and producer tests remain executable. No new external request keys are introduced by this test plan.
