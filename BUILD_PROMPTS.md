# Build workflow prompt review

Source snapshot: `c505b9926fdb2637f61c525b01d3c2f001e150b2`. This is a review copy of the recipe-owned prompts in
`build.yaml` and its light/heavy workflows, shared helpers, and delegated cell
creation flow. It fits this cell's responsibility for workflow instructions.
No recipe behavior has been changed by preparing this document.

Each numbered heading identifies a source file and YAML field. Use the prompt
number or source location when requesting changes; you can also edit this review
copy and return it. Source files remain authoritative until edits are applied.
Sequence indices in field paths are zero-based. Source links point to this snapshot's
line locations; line numbers may move in later edits.

Text blocks preserve YAML-decoded prompt wording, including template placeholders,
with whitespace-only wrapping of long prose lines for reading.
CEL blocks preserve expressions that assemble prompts or select conditional text;
they are not examples of fully rendered job prompts. Literal message strings nested
in CEL maps are extracted without their surrounding state updates. YAML blocks show
human questions with their response choices. Repeated source locations remain separate
so changes can target either workflow. These excerpts are not rewritten recommendations.

The build combines several layers:

1. The submitted request becomes the initial workflow message. The classifier uses
   the request and repository purpose/architecture to select light or heavy work.
2. Light work combines setup, the current message, and repository implementation guidance.
   Heavy work adds design, test-plan, or implementation instructions when entering a phase.
3. The shared agent wrapper appends artifact-directory instructions. New sessions receive
   `instructions`; resumed sessions receive a new prompt and the saved session. The caller's
   assembly expressions determine when setup or phase instructions are repeated.
4. Coordination, feedback, preparation, verification, and rebase recovery replace the
   current message before the next turn. Repair prompts and their diagnostic artifacts
   are included below, as are independent assessment and merge-review prompts.
5. Human questions are fixed at review gates or generated by an agent. Optional review
   synthesis has its own model prompts and only runs when its activation/provider/model
   gates allow it.

Repository-specific `AGENTS.md`, purpose documents, supplied artifacts, saved session
history, user feedback, and configure-hook `prompt_additions` contribute additional
context at runtime. They vary by target repository and job and are not expanded here.
The final entries show the configure-hook **example**, not active shared defaults.
This repository's `.c2/recipes/hooks/build/verify.yaml` runs a shell check and contains
no model prompt. Other cells may implement their hooks with additional prompts.

This inventory covers the current `build.yaml` call paths, including their default
consultation and creation recipes. It excludes separate `new-ticket`, `superpowers`,
standalone job recipes, smoke fixtures, and tests. Customized remote recipes and hooks
can add prompts outside this snapshot. Native c2j/c2ops launcher instructions belong to
those components and are not reproduced. Output schemas and executable validation
logic also constrain responses; consult the linked source for the complete contract.
Response-repair feedback expressions are included when they supply authored direction,
but arbitrary error messages produced by tools are not enumerated.
